# 설계 설명

## 현실과 디지털 상태의 연결

이 버전의 트윈은 수동 기록으로 동기화됩니다. 실제 집을 자동 관측하지 않으므로 사용자가 이동·소비·폐기를 기록해야 합니다. 공간은 각 부모 안에서 20×20 상대 좌표를 갖습니다. 겹침을 허용하며 건축 치수나 충돌 검증을 의미하지 않습니다. 2D 표현만으로 먼저 ‘등록한 물건을 다시 찾는가’를 검증합니다.

## 모델을 나눈 이유

| 모델 | 책임 | 원본과의 차이 |
|---|---|---|
| Household | 집과 공동 설정 | 실제 초대 가입, 변경 가능한 임박 기준 |
| User | 인증과 가구 소속 | 한 사용자 한 가구, 가입 시 합류 선택 |
| Location | 방/가구/수납 칸과 상대 배치 | 좌표·크기·종류·순환 방지 |
| Product | 상품 정체성, 바코드, 구매 기준 | 같은 상품의 여러 재고를 연결 |
| Batch | 상품+위치+유통기한별 수량 | 유통기한 없음은 빈 문자열로 고유 제약 적용 |
| Activity | 재고 변화를 설명하는 불변 기록 | 당시 이름/경로 보존, 폐기/정정/이동 분리 |

상품명은 공백과 대소문자를 정규화하여 같은 가구 안에서 중복을 막습니다. 동일 상품명에 다른 규격이 필요하면 이름에 규격을 넣으세요. 상품 하나에 바코드 하나와 단위 하나를 지원합니다. 정수 수량은 개수 또는 포장 수이며, 잔량형 상품은 Batch의 개봉 상태와 대략적인 잔량을 별도로 관리합니다. 변경 사항과 제약은 [피드백 반영 문서](FEEDBACK.md)를 참고하세요.

## 재고 불변 조건

- 수량은 0 이상입니다. DB CHECK와 요청 검증을 함께 사용합니다.
- 부분 이동은 출발 재고 감소 + 도착 배치 합산 + 이동 이력을 같은 트랜잭션으로 저장합니다.
- 낙관적 잠금: `version`이 읽은 값과 같은 경우만 UPDATE합니다. 동시에 수정됐으면 409로 다시 확인하게 합니다.
- 같은 배치의 동시 첫 등록은 고유 제약이 충돌을 감지합니다. 자동 재시도하지 않습니다.
- 빈 재고도 보존하여 Activity의 참조가 끊어지지 않게 합니다.
- 활동 이력에 수정/삭제 API는 없습니다. DB 관리자까지 수정 불가능한 감사 저장소는 아닙니다.
- 이름이나 위치 이름이 바뀌어도 과거 이력의 스냅샷은 바뀌지 않습니다.
- 물건/이력이 연결된 위치는 삭제를 막습니다. 향후 보관 종료(archive)를 별도 설계할 수 있습니다.

## 예측과 학습 누수

1. 최초 재고 기록부터 최근 최대 90일 중 완료된 날짜만 관측합니다. 오늘은 부분 관측이라 학습하지 않습니다.
2. `consume`만 사용량으로 집계합니다. `discard`, `move`, `adjust`는 제외합니다.
3. 완료 7일 미만 또는 소비가 있는 날 3일 미만이면 추정하지 않습니다.
4. 기본은 최근 14일 평균입니다.
5. 28일 이상, 소비일 8일 이상이면 Ridge 회귀를 후보로 학습합니다. 특성은 시간 추세와 요일의 sin/cos입니다.
6. 마지막 7일을 검증용으로 떼어 ML과 평균 기준선의 MAE를 비교합니다. ML이 개선할 때만 전체 관측으로 재학습해 다음 7일 일평균을 계산합니다.
7. 만료 재고를 제외한 사용 가능 수량 / 일평균 소비량으로 대략적인 소진일을 구합니다.

예측일은 확률 구간이나 보장된 소진일이 아닙니다. 기록하지 않은 날은 사용량 0으로 처리하므로 기록 누락이 많으면 편향됩니다. 하루 0.001개 미만의 작은 값은 표시 반올림의 영향을 받습니다. 실제 재고 실사와 기록 습관이 모델보다 먼저입니다. 상품별 데이터가 작으므로 이 구조는 ML 학습 과정을 이해하는 참고 구현입니다.

## 프론트와 백엔드 연결

빌드 도구를 도입하기 전에 익숙한 HTML/CSS/JS와 FastAPI를 유지했습니다. `/api`는 API, `/`는 정적 프론트입니다. 프론트에서 production API URL을 하드코딩하지 않으므로 기존 테스트 서버에 실수로 쓰지 않습니다.

폼은 위치 조회가 끝날 때까지 빈 화면을 보여 주지 않습니다. 초기 상태를 한 번 불러온 뒤 화면을 그립니다. 네트워크 요청에는 제한 시간이 있으며 저장 시간 초과 시 중복 재시도 전에 목록을 확인하도록 안내합니다. 현재 자동 동기화/WebSocket은 없으며 다른 가족의 변경은 새로고침으로 확인합니다.
