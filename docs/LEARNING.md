# 기능별로 비교하며 배우기

원본을 먼저 읽고, 참고 구현을 실행하고, 이유를 설명한 다음 작은 확장을 직접 구현하세요. 한 번에 모든 파일을 이해하려고 하지 않아도 됩니다.

## 1. 원본에서 출발

`reference/original/main.py`, `reference/original/frontend.html`을 읽습니다. 로그인부터 등록까지 요청이 어떤 순서로 이어지는지 직접 적어 보세요. 기존 파일은 참고 자료이며 이 앱 실행에 import하지 않습니다.

질문: 화면에 버튼이 있다는 사실과 기능이 실제 동작한다는 사실은 어떻게 다른가? 원본 `simulateScan()`은 무엇을 하고 있었는가?

## 2. 물건을 세 덩어리로 나누기

`models.py`의 Product → Batch → Activity를 읽습니다. 우유 2개가 냉장고에 있고, 다른 유통기한 우유 3개가 창고에 있을 때 행을 몇 개 만드는지 종이에 그리세요.

직접 해 볼 확장: 상품의 카테고리를 추가하고 검색 필터로 연결하세요. 기존 DB를 바꿀 마이그레이션도 함께 고민하세요.

## 3. 하나의 요청을 끝까지 따라가기

프론트 `itemDialog()` → `api.js` → `/api/items/{id}/actions` → `change_quantity()` → `log()` 순서로 읽습니다.

질문: 이동 중 도착 위치가 다른 집 소유라면 어디서 막히는가? 중간에 실패하면 원래 수량은 어떻게 되는가? 로그를 먼저 커밋하면 어떤 문제가 생기는가?

직접 해 볼 확장: 이동 취소를 ‘과거 기록 삭제’ 없이 새 반대 이동으로 구현하세요. 다른 소비가 이미 일어난 경우의 제약도 정하세요.

## 4. 공간 탐색

`path_for()`, `descendants()`, `homeView()`, `bindDrag()`를 읽습니다. 좌표는 부모 공간 기준이며 20을 넘지 않게 검증됩니다.

질문: 주방을 자기 냉장고 안으로 옮기는 요청이 왜 실패해야 하는가? 마우스 좌표를 배치 좌표로 어떻게 바꾸는가?

직접 해 볼 확장: 공간 겹침 경고를 만들되, 겹침을 무조건 금지하는 것이 사용자에게 맞는지도 판단하세요.

## 5. 인식 결과를 믿는 범위

`lookupBarcode()`와 `recognition.py`를 읽습니다. 상품 인식은 입력 보조이며 물건을 자동 확정 저장하지 않습니다.

직접 해 볼 확장: 사진에서 여러 물건이 발견되면 후보 목록을 보여주고 하나씩 확인하도록 바꾸세요. 모델 오답과 네트워크 실패를 분리해 설명해 보세요.

## 6. 예측 실험

`intelligence.py`와 `tests/test_forecast.py`를 읽습니다. Ridge가 항상 선택되지는 않습니다. 합성 데이터의 추세를 바꿔 검증 MAE와 선택 모델이 어떻게 바뀌는지 관찰하세요.

질문: 무작위 train/test split을 쓰면 왜 위험한가? 재고가 0인 동안의 미관측 수요를 소비 0으로 보면 어떤 편향이 생기는가?

직접 해 볼 확장: 날짜별 재고 부족 구간을 표시하고, 예측을 중단하거나 관측 누락으로 처리하는 방식을 설계하세요.

## 커밋 읽는 법

```bash
git log --oneline --reverse
git show <보고 싶은 커밋>
git diff <앞 커밋> <뒤 커밋> -- backend/inventory.py
```

커밋은 원본 보존 → 백엔드 → 프론트 → 검증과 문서 순서입니다. 중간 커밋은 학습 단계의 스냅샷이므로 최종 커밋에서 실행하세요. 정답을 암기하기보다 변경 이유를 자신의 말로 설명하고 다음 확장을 직접 구현하는 데 사용하세요.
