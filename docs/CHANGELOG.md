### feat: 유통기한 푸시 알림

- 매일 아침 “유통기한 임박 N개: 두부, 우유 · 장보기 N개: …” 요약을 알림을 켠 기기로 보냅니다. 알릴 것이 없으면 보내지 않습니다. 알림을 누르면 앱의 알림 화면이 열립니다.
- **설정 → 유통기한 알림**: 켜기 / 테스트 알림 보내기 / 끄기. 아이폰에서 홈 화면 앱이 아니면 추가 방법을, 권한이 차단됐으면 해제 방법을 안내합니다.
- **백엔드**: `push_subscriptions` 테이블(새 테이블이라 `create_all`로 기존 DB에도 생성), API `GET /api/push/key`, `POST /api/push/subscribe|unsubscribe|test`, `/api/me`에 `push_enabled`.
- **발송**: `python -m backend.push`를 cron으로 매일 실행. `--keys`로 VAPID 키 생성. 만료된 구독(404/410)은 자동 삭제.
- **보안**: 서버가 구독 주소로 요청을 보내므로 SSRF를 막기 위해 FCM·Mozilla·Apple·Windows 푸시 도메인만 허용. 로그아웃하면 그 기기 구독 해지(다른 계정 알림 방지). 같은 기기에서 다른 계정으로 켜면 구독 소유자가 바뀝니다.
- **서비스워커** `sw.js`: 푸시 수신과 알림 클릭만 처리(오프라인 캐시 없음). 알림을 켤 때만 등록합니다.
- 알림 계산(`household_insights`)을 `intelligence.py`로 옮겨 화면 API와 발송이 같은 로직을 씁니다.
- 의존성 추가: `pywebpush==2.5.0`(RFC 8291 암호화와 VAPID 서명은 직접 구현하지 않음). 기존 `cryptography` 고정 버전과 호환.
- 검증: `pytest` 24 passed(키 쌍 일치, 키 없을 때 비활성, 내부망·HTTP·유사 도메인 구독 거부, 기기 소유자 이동과 남의 구독 해지 불가, 발송 문구와 만료 구독 삭제). 헤드리스 Chrome은 실제 FCM 구독이 불가해 `PushManager`를 흉내 내 켜기/끄기/로그아웃 해지/알림 클릭 이동을 E2E로 확인. **실기기 수신은 미검증.**

- 쓰이지 않던 CSS(`.span2`, `.progress`, `.photo-preview`, `.list`, `.mobile-title`) 삭제.

### feat(pwa): 홈 화면에 앱으로 설치

- `manifest.webmanifest`와 아이콘(192/512/maskable/apple-touch)을 추가했습니다.
- `viewport-fit=cover`로 노치·홈 인디케이터 영역까지 그리고 safe-area로 여백을 맞춥니다.
- iOS: 사파리 공유 → 홈 화면에 추가. Android: Chrome 메뉴 → 앱 설치.
- 서비스워커(오프라인)는 넣지 않았습니다. 모든 데이터가 서버에 있어 오프라인 화면만으로는 쓸 일이 없기 때문입니다.
